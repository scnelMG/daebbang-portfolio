# 추천 결과가 비는 문제와 탐색 슬롯

## 관측

당시 팀의 문제 분석 문서에는 등록 빵집 106곳, 점수 보유 59곳, 추천 요청 47회 중 빈 결과 7회가 기록돼 있습니다. 특정 빵과 드문 유형 태그 조합에서는 점수 후보가 없었습니다. 이는 기존 운영 시점의 기록이며 공개본에서 재측정한 수치는 아닙니다.

## 원인

리뷰가 있어야 점수를 만들고 점수가 있어야 추천 후보가 됩니다. 후기가 없는 가게는 추천에서 빠지며, 사용자가 방문하고 내부 리뷰를 남길 기회도 적습니다. 검색어를 늘리는 것만으로 원래 존재하지 않는 리뷰를 만들 수는 없습니다.

## 선택과 대안

| 대안 | 검토 |
| --- | --- |
| 수집량 늘리기 | 없는 데이터 자체를 해결하지 못하고 소스별 수집 제약이 있음 |
| 모든 가게에 임의 점수 부여 | 근거 없는 점수를 추천 근거처럼 보여줄 수 있음 |
| 후보 커버리지 완화 | 기존의 최소 근거 기준이 약해짐 |
| 점수 추천과 탐색 슬롯 분리 | 기존 계산을 유지하면서 새로운 가게를 노출할 수 있음 |

구현은 점수 추천 최대 2곳을 유지하고 나머지를 무작위 탐색으로 채웁니다. 탐색은 영업 중이고 이미 뽑히지 않은 가게 전체에서 선택합니다. 리뷰가 없는 가게만 우선하는 가중 정책은 구현하지 않았습니다.

## 확인과 한계

코드에서 `pickType=score|random` 구분과 프론트엔드의 ‘오늘의 발견’ 표시를 확인할 수 있습니다. 공개 미리보기에서는 고정된 가상 응답으로 이 UI 계약을 확인했습니다. 실제 추천 알고리즘을 미리보기 서버가 실행하는 것은 아닙니다.

영업 중인 서로 다른 가게가 충분할 때 결과를 최대 3곳까지 채웁니다. ‘모든 상황에서 3곳 보장’은 정확한 설명이 아닙니다. 변경 후 빈 결과율·방문율·내부 리뷰 유입률을 재측정한 자료는 이번 공개본에 포함하지 않았습니다.
